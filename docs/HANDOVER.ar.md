# دليل تسليم نبض

آخر تحديث: 2026-11-18 · **الإصدار 7.0.0** · سجل التغييرات: `CHANGELOG.md`

هذا الملف أول ما يقرؤه من يستلم المشروع. يقول ما هو نبض، وكيف يُشغَّل، وأين كل شيء، وما الذي يعمل وما الذي لا يعمل بعد.

---

## 1. ما هو نبض

منصة تدريب سريري بالعربية لطلاب الطب والتمريض. المتدرب يدير مريض طوارئ في غرفة محادثة: يكلّم المريض والمرافق، يعطي أوامر للممرض، يقرأ المونيتور، يطلب الفحوصات، يسلّم المريض، ثم يأخذ تقريراً مفصلاً. الجامعة تشترك وتنظّم طلابها ومشرفيها وتختار من حالات نبض، والمشرف يراجع جلسات طلابه ويعتمد درجاتهم.

**حالة المشروع:** نموذج أولي (prototype) للعرض على لجنة المسابقة والعميل.
- الواجهة كاملة ومترابطة على بيانات عرض.
- **لا خادم بيانات ولا قاعدة بيانات بعد**: الحسابات والجلسات محفوظة في متصفح الجهاز.
- **المحتوى السريري لم يراجعه طبيب بعد.**

## 2. التشغيل

المطلوب: .NET 10 SDK. (Node.js اختياري، لأدوات الفحص فقط.)

```bash
dotnet build Nabd.sln
```

```bash
dotnet test Nabd.sln
```

```bash
dotnet run --project src/Nabd.Web --launch-profile http
```

ثم افتح `http://localhost:5054`. في وضع التطوير خدمات الفهم المدفوعة مطفأة والغرفة تعمل بوضعها المحلي (offline). التفاصيل في `docs/setup.md`.

## 3. الحسابات للعرض

| الدور | كيف تدخل | ماذا يرى |
|---|---|---|
| إدارة منصة نبض | زر «إدارة نبض» في شاشة الدخول | المؤسسات، المستخدمون، الاشتراكات، الحالات ومراجعتها، المصادر، قواعد التقييم، السجل، الإعدادات |
| مدير جامعة | زر «مدير الجامعة» | المساقات والشعب، الكادر، الطلاب (قائمة البريد)، مكتبة الحالات (فتح وإغلاق)، التقارير، إعدادات الجامعة وعلامات النجاح |
| مشرف أكاديمي | زر «مشرف أكاديمي» | شعبه فقط: إسناد الحالات، طلابه، النتائج والاعتماد |
| طالب جامعة | بريد من القائمة: `zaid.a@uni1.edu.jo` (طب)، `rana.m@uni1.edu.jo` (تمريض) | الرئيسية، الطوارئ، واجباته الجامعية، تقاريره ومراجعة المشرف، المدرب السريري |
| متدرب مستقل | أي بريد جديد ← ينتقل إلى إنشاء الحساب (الاسم، المسار، السنة) | مثل الطالب دون القسم الجامعي |

قبل أي عرض: «إدارة نبض» ← الإعدادات ← «إعادة ضبط بيانات العرض». سيناريو العرض خطوة خطوة في `docs/demo-script.ar.md`.

## 4. البنية

### الخادم: خمسة مشاريع بالبنية النظيفة (Clean Architecture)

```
src/
  Nabd.Domain/          نموذج المحاكاة السريرية (بلا أي اعتماد خارجي)
  Nabd.Application/     حالات الاستخدام والمنافذ (ports)
  Nabd.Infrastructure/  بيانات الحالات، مخزن الجلسات، بوابة الخدمات الخارجية
  Nabd.Web/             MVC: المتحكمات، صفحات Razor، سكربتات المتصفح، الملفات الثابتة
tests/
  Nabd.Tests/           207 اختبارات: بنية، مجال، golden masters، تطبيق، بنية تحتية، ويب، واجهة
```

الاعتماد باتجاه واحد نحو الداخل (Web ← Application ← Domain)، واختبار `LayeringTests` يمنع العكس.

### داخل Nabd.Web (MVC)

| المجلد | فيه |
|---|---|
| `Controllers/` | المتحكمات: الصفحة، الدخول والتسجيل، السكربتات، البيانات، الـAPI |
| `Views/` | صفحات Razor مقسّمة لأجزاء: `Home/Landing` (الواجهة العامة)، `Home/Dashboard` (الرئيسية بعد الدخول)، `Account` (الدخول والتسجيل)، `Shared/Layout` (الرأس والتذييل) |
| `ClientScripts/` | سكربتات المتصفح، تُجمع في حزم حسب `bundles.json` (انظر الجدول التالي) |
| `Images/` + `images.json` | كتالوج الصور: كل صورة بمفتاح، والصفحات تكتب المفتاح |
| `wwwroot/` | CSS والصور والخطوط |

### سكربتات المتصفح: كل حزمة لمسؤولية واحدة

| الحزمة | المجلد | مسؤوليتها |
|---|---|---|
| `script.js` | `script/` (24 ملفاً) | قشرة التطبيق: الحساب والجلسة، شاشة الدخول، التنقّل، القائمة الجانبية، الملف الشخصي، القسم الأكاديمي للطالب، الرئيسية حسب المسار |
| `er.js` (+ `motion.js`, `terms.js`) | `er/` … | **غرفة الطوارئ المعتمدة**، محمية ببصمة في الاختبارات؛ لا تتغيّر إلا بقرار المالك |
| `ui.js`, `landing.js` | `ui/`, `landing/` | درج القائمة الجانبية؛ الواجهة العامة وصفحات الدخول |
| `admin.js` | `shared/` + `admin/` | مخزن المتصفح (`NabdStore`)، ثم لوحات الإدارة الثلاث |
| `app.js` | `app/` (11 ملفاً مرقّماً) | تطبيق المتدرب: قواعد الدخول، من يرى ماذا، الرئيسية، التقارير، المدرب السريري وتمارينه، الملف الشخصي، القائمة الجانبية وزر الرجوع |
| `er-plus.js` | `erplus/` | طبقات فوق غرفة الطوارئ: الواقعية، التقييم، مكالمة الممرض والطبيب، فتح حالة، قفل الدور |

وأوراق الأنماط بنفس التقسيم: `admin.css` (الإدارة)، `trainee.css` (شاشات المتدرب)، `er.css` (الغرفة المعتمدة)، `er-plus.css` (طبقات الغرفة)، `home.css` (الرئيسية)، `landing*.css` (الواجهة العامة)، `auth.css` (الدخول).

**كل قراءة وحفظ للبيانات يمرّ عبر `NabdStore`** (`ClientScripts/shared/010-store.js`). يوم يُبنى الخادم، يتغيّر هذا الملف وحده ليصير عميل API.

## 7. ما يعمل وما لا يعمل بعد

| يعمل في النموذج | لا يعمل بعد |
|---|---|
| دخول واحد للجميع، والبريد يحدد الدور والجامعة | كلمة مرور حقيقية ومصادقة على خادم؛ الدخول بحساب Microsoft/Google («قريباً») |
| غرفة الطوارئ بست حالات، بدور الطبيب أو الممرض حسب المسار | الغرفة التنفسية والحالات التخصصية (ظاهرة «قريباً») وغرف العمليات ثلاثية الأبعاد |
| تقييم مفصّل: محاور، أخطاء بالخطورة، خط زمني، تسليم، تأمل | التقييم بالموديل (الإيجنت) كلمة كلمة: القواعد اليوم ثابتة |
| الجلسة تصل للمشرف، يعدّل بسبب مكتوب، وينشر، وتعود للطالب | على نفس المتصفح فقط: لا مزامنة بين أجهزة |
| المدرب السريري: يقرأ التقارير، يسمّي النقص، وتمرين موجّه واحد مكتوب (كبار السن) | تمارين يرتجلها الإيجنت؛ بقية قوالب التمارين |
| لوحات الإدارة الثلاث على بيانات عرض | الاشتراكات والفوترة الحقيقية |
| اختبار المستوى | **مؤجّل** (الزر مخفي) |

## 8. قواعد ثابتة

1. لا سر ولا مفتاح API في المستودع ولا في كود المتصفح.
2. غرفة الطوارئ المعتمدة لا تُعدّل؛ الإضافات طبقات في `erplus/`، وبصمتها في `SiteAssetsTests` تكشف أي تغيير.
3. لا كود غير مستعمل: أي صفحة أو دالة أو قاعدة CSS أو صورة أو ملف بيانات لا يستعمله شيء يُحذف (القرار 0021). وتغيير منطقة مصمّمة يُعتمد بـ `tools/approve-regions.mjs`.
4. كل تعديل: البناء والاختبارات تنجح، وجولة في المتصفح على 1440 و390.
5. المستودع المنشور (`nabd5`) يُرفع بتاريخ جديد فقط، دون تاريخ التطوير.
